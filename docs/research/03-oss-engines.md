# OSS engines and editors for fframestudio

**Checked:** 2026-10-17 (live GitHub API and first-party documentation).  
**Scope:** web-first, theme-agnostic video studio; responsive/PWA mobile; optional desktop shell. Research and architecture recommendation, **not a runtime qualification or legal opinion**. No engine was installed, benchmarked, or rendered in this survey. Performance, export fidelity, and end-to-end mobile compatibility remain **UNVERIFIED** unless explicitly described as upstream documentation rather than our test result.

## 1. Decision in brief

**Reuse an existing composition/media engine before building one.** The strongest browser-first starting candidates are **WebAV** (MIT, reusable editing SDK) and **Diffusion Studio Core** (MPL-2.0, fuller compositor, but unresolved watermark/key terms). **OpenReel** is the most useful newly discovered full-editor reference to evaluate alongside them. Do not select OpenCut merely by its stars: its main repository is a rewrite, while its usable classic tree is archived.

Recommended initial architecture:

- **Preview and browser export:** WebAV `@webav/av-canvas` + `@webav/av-cliper`, behind an engine adapter. Reuse its clip/sprite/combinator semantics, not a home-grown decoder, playback loop, or muxer. Validate the restricted initial feature set before committing. Its documented Chromium/Electron support is not a universal-browser promise.
- **Broader media I/O:** Mediabunny (MPL-2.0) for probing, thumbnails, conversion/proxies and formats outside the initial WebAV path. Do not decode the same active clip twice; give each adapter explicit ownership. If the WebAV spike fails, prefer adopting a qualified existing compositor (Diffusion Core after legal clearance, or OpenReel code after tests) over immediately writing a Pixi engine.
- **Export:** same browser composition implementation for visual parity; headless Chromium running that adapter plus an audited native FFmpeg build for server/desktop fallback. **fframes is a valuable optional native motion-graphics backend**, not an assumed drop-in JSON renderer or the sole export implementation.
- **Document:** a small, versioned declarative JSON envelope with stable IDs and rational time, mapping to reused engine objects. OTIO for editorial interchange, not as an all-purpose scene graph or renderer.
- **Plugins:** declarative effect/template manifests first; capability-scoped browser workers and isolated-origin sandboxed iframe UIs when executable plugins are needed. Do not build a scripting language or give plugin code desktop IPC access.
- **Collaboration:** Yjs for document state, awareness and collaborative undo; assets stay outside the CRDT. Automerge is the alternative if Rust-first history/branching becomes more important.
- **Desktop:** Electron initially if Chromium codec consistency is required by the chosen engine. Tauri remains the preferred smaller Rust shell **only after** the actual WKWebView/WebKitGTK/WebView2 matrix passes; a Rust backend does not make browser preview features portable.
- **Assistive features:** Transformers.js for optional local browser captions; whisper.cpp for native captions; MediaPipe for initial background masks; `web-audio-beat-detector` for an editable fixed-tempo suggestion, not authoritative beat/downbeat detection.

This is a **conditional stack selection with explicit gates**, not a claim that these components already interoperate. The product differentiation is the simple authoring model, themes, templates, agent/human operations and portability—not a new codec stack.

## 2. Evidence method and GitHub maturity ledger

For every repository below, collection used the authenticated `gh` CLI:

```sh
gh api repos/OWNER/REPO
gh api 'repos/OWNER/REPO/commits?per_page=1'
gh api repos/OWNER/REPO/license
gh api repos/OWNER/REPO/readme
gh api 'repos/OWNER/REPO/contributors?per_page=100' --paginate --slurp
gh api graphql -f query='query { repository(owner:"OWNER",name:"REPO") { issues(states:OPEN) { totalCount } pullRequests(states:OPEN) { totalCount } } }'
```

Definitions and limitations:

- **Stars** are `stargazers_count`, not a quality score. **Commit** is the committer date of the latest default-branch commit, linked to its exact SHA—not `updated_at` or `pushed_at`.
- **Issues** are GraphQL open issues, **excluding PRs**. REST `open_issues_count` combines issues and PRs and was not used for that column.
- **Contrib.** is the count of accounts returned by fully paginating GitHub's contributors endpoint; includes bot accounts when returned, excludes anonymous contributors, and is subject to GitHub caching/author limits. It is neither current maintainers nor bus factor. Fork histories can inflate counts.
- **API licence** is GitHub's literal detection, not our legal conclusion. `NOASSERTION` or `null` is not permission. Exact package/source qualifications are in the evaluation tables and licence traps below.
- **Archived** is the API flag; a repository can be unmaintained without being archived. GStreamer's GitHub mirrors do not host the upstream issue tracker, so zero GitHub issues is not zero bugs. Development happens on [freedesktop GitLab](https://gitlab.freedesktop.org/gstreamer/gstreamer). FFmpeg likewise has GitHub issues disabled; its zero is a tracker configuration, not a defect count, and its README directs contributions outside GitHub.
- Numbers are a dated snapshot and will change. README feature claims are not benchmark results. Licence links and commit links make the inspected revision recoverable; recheck the exact release tarball, lockfile and binary configuration before distribution.

### What fframes actually changes about the seed

The inspected local seed is `<seed studio repo>/scripts/studio/studio.js`, especially lines 634–644. `exportSpec()` emits **`schema: 'pretotype-film/1'`**, direction/narrative, soundtrack attribution, runtime, `fps: 60`, `[1920,1080]`, honesty/watermark metadata and timed shots. A toast says “the fframes build reads this file.” **That toast is not evidence that a reader exists or accepts arbitrary film specs.** This survey inspected the exporter, not a working downstream adapter.

Upstream fframes' documented contract is Rust `Video::render_frame(...)` returning an SVG tree. Its [crate manifest](https://github.com/dmtrKovalenko/fframes/blob/main/fframes/Cargo.toml) declares MIT and codec feature gates. Therefore:

1. Preserve the seed JSON as a migration input; do not call it fframes' native schema.
2. Build a small importer that resolves assets and maps shot semantics into the studio's versioned document.
3. For fframes, build a **trusted data-driven renderer adapter** or generate reviewed Rust templates. Never compile arbitrary uploaded Rust as a normal user-plugin mechanism.
4. Validate typography, masks, transitions, source-video timestamps, audio offsets and color against the browser reference. Native SVG/Skia versus browser DOM/Canvas is a real fidelity boundary.
5. Keep an escape hatch: prerender an unsupported motion scene into an intermediate clip rather than maintaining two incomplete implementations of every effect.

fframes' benchmark statements are upstream examples, **not comparative measurements made here**. Its MIT licence is real, but a linked static libav/x264/x265 binary can have materially different distribution obligations. In particular, the README's Windows example uses a GPL FFmpeg shared build. Avoid `libav-agree-nonfree` in redistributed builds unless the exact combined distribution rights are established; “nonfree” is not an SPDX licence.

### Browser portability is a capability matrix, not a checkbox

Define explicit tiers:

1. **Full editing/export:** tested WebCodecs encode/decode combinations, Web Audio, sufficient memory/storage and a functioning compositor backend.
2. **Edit/preview + remote/native export:** browser cannot encode the delivery format but can preview supported proxies.
3. **Review/basic authoring:** low-memory/mobile cases; lower-resolution proxies and a deliberately reduced effect set. A PWA does not guarantee background exports survive OS suspension.

Test Chrome, Edge, Firefox and Safari plus Android Chrome and iOS Safari/PWA. Do not infer Safari support from Chromium results. Codec availability depends on profile, level, alpha, resolution, browser build and OS. H.264 decode support does not imply AAC encode support. CORS-tainted sources, fonts not loaded, storage quotas, GPU context loss, VFR timestamps and rotation metadata can break otherwise simple demos.

Use the same time-to-frame contract for preview and export. Export offline by explicit timestamps—not by hoping realtime `MediaRecorder` captures every frame. Free resources/VideoFrames promptly, respect decoder/encoder backpressure, stream to storage, and support cancellation. Native FFmpeg broadens codec coverage but cannot magically reproduce DOM/CSS or all WebGL effects.

### Minimal canonical film document

Own a **thin product schema**, not an alternative to every upstream engine model:

- Schema/version, document ID, render dimensions, rational frame rate and timebase; integer/rational timeline positions instead of accumulating rounded seconds.
- Content-addressed assets with source attribution, licence, fingerprints, media properties and portable relative references; separate local handles and expiring URLs from canonical identity.
- Stable shot/clip/track IDs, source in/out, timeline start/duration, gain and validated transitions. Explicit source-time mapping for speed changes and VFR material.
- Typed text/shape/media/template nodes, parameterized motion curves, font references and semantic theme tokens. Keep editor chrome themes separate from film themes.
- Captions, beat/downbeat annotations with confidence and user corrections, review notes and provenance. Preserve the seed's honesty metadata rather than silently discarding it during rendering.
- Engine-neutral effect identifiers plus versioned adapter capability declarations. Unsupported effects must produce a visible error or documented prerender, not quietly disappear.

A Yjs document stores this logical data; an export job gets an immutable, validated snapshot plus asset manifest and engine versions. Renderer state, decoded frames, waveforms and blobs are caches, not CRDT content. CRDT convergence alone does not guarantee legal clip ranges, useful concurrent ripple edits, permission checks or correct undo semantics; those remain product operations and tests.

## 8. Licence traps that affect this product specifically

1. **Source available is not OSS.** Remotion, Twick and GSAP belong in the comparison but not in the unrestricted OSS shortlist. Their current commercial restrictions target precisely some of the ways an editor/SDK business could operate.
2. **Root licence is not package licence.** Theatre's Apache root does not cover Studio's AGPL terms. Tauri's actual dual licence is broader than the API detection. Yjs's actual MIT text is clearer than `NOASSERTION`.
3. **Wrapper licence is not codec licence.** fframes, editly, Electron, ffmpeg.wasm and any native Mediabunny extension need dependency/binary audit. Preserve configure flags, notices, corresponding source and relinking obligations where applicable; no unreviewed GPL/nonfree prebuilts.
4. **Copyleft is not non-commercial.** GPL/AGPL allow commercial use under their conditions. Shipping JS/WASM to a browser distributes code; “it runs client-side” is not an exemption. An iframe or subprocess is not a reliable way to evade obligations for an integrated derivative.
5. **MPL can fit a proprietary product.** Keep modified MPL-covered files available under MPL and comply with source/notice requirements; separate new product files can have another licence. Do not claim every application file must become MPL—or that MPL is identical to MIT.
6. **Diffusion's ambiguity needs resolution.** LICENSE is MPL-2.0; README markets paid watermark removal and signed keys. This survey does not decide enforceability or recommend bypassing a check. Obtain written terms or select another engine.
7. **GSAP's change is material but not permissive relicensing.** The standard licence is effective April 30, 2025, modified May 30, 2025 in the retrieved page; it still bars certain competing visual builders. HyperFrames being Apache-2.0 does not erase the GSAP adapter's terms.
8. **Assets and branding are separate.** Rive/Lottie templates, music, fonts, stock-provider API results and Diffusion brand assets require their own grants. Preserve the seed soundtrack attribution. Rebranding a fork must not imply upstream endorsement.
9. **Models are separate.** Especially Essentia's NC/ND models, MediaPipe task files and arbitrary Hugging Face checkpoints. SAM/SAM 2 model grants do not grant their research datasets identical rights.
10. **Pin before shipping.** The ledger is not an SBOM. Create a lockfile-level SBOM with package/version/source/SHA, SPDX or preserved custom terms, notices, patches, build flags and approved redistribution mode. Route unclear `-only` versus `-or-later` cases to legal review rather than silently “correcting” the source token.

## 9. What should be reused versus built

### Reuse, not bespoke

- Media decode/encode, container parsing/writing and streaming/backpressure: WebAV/Mediabunny/WebCodecs, audited FFmpeg for native paths.
- Existing clip composition/direct manipulation wherever the WebAV gate passes; otherwise qualify Diffusion Core/OpenReel rather than immediately replacing them.
- GPU drawing/filter primitives: PixiJS only if needed; animation assets: dotLottie/Rive runtimes with asset rights.
- CRDT convergence: Yjs or Automerge, plus existing provider/persistence modules after licence review.
- Editorial interchange: OTIO adapters; speech: Whisper-based runtimes; segmentation: MediaPipe/SAM; analysis: existing MIR libraries.
- OS packaging/webview integration: Electron or Tauri. Use browser/OS sandbox primitives rather than inventing a VM.

### Build the thin product/integration layer

1. **Simple UI and theme system:** responsive layout, keyboard/touch accessibility, constrained workflow, themeable editor chrome and film templates. Reuse isolated timeline/actions from an editor only after tests and licence retention; do not fork an entire complex NLE merely to get a scrubber.
2. **Canonical document and seed importer:** schema validation/migrations, stable IDs, rational-time helpers, asset references, template parameters and provenance. Avoid coupling saved projects to a vendor's in-memory object graph.
3. **Editing command API:** split/trim/move/ripple, undo transactions, permissions and deterministic agent operations. Human UI and MCP/automation should invoke the same validated commands.
4. **Engine adapters/capability negotiation:** document-to-engine mapping; browser/native export manifests; supported effect lists; explicit failure/prerender behavior. Not new codecs.
5. **Asset pipeline and persistence:** portable project bundle, browser storage/relinking, thumbnail/waveform/proxy caches, offline recovery and optional object-store sync. Do not put media blobs in a CRDT.
6. **Export orchestration:** immutable snapshots, queue/progress/cancel/resume, platform/codec selection, resource ceilings and output verification. Route unsupported mobile exports to a user-approved server or desktop job.
7. **Plugin contract/security:** typed schemas, versioning, capability grants, origin isolation, message validation, resource limits and review/signing. Worker isolation alone does not remove network access; enforce CSP/origin restrictions and never expose the desktop bridge to untrusted plugins.
8. **Collaboration semantics:** project ACLs, asset access, presence, offline recovery, conflict UX, per-user undo and validation after concurrent edits. CRDT libraries do not supply all of this.
9. **AI/analysis UX:** caption correction and timing tools, editable masks, beat-grid override, confidence/provenance, model downloads and cache lifecycle. No bespoke ASR/segmentation engine.
10. **Fidelity and compatibility harness:** golden frames/audio, codec probes, project migrations, crash recovery and multi-device tests. This is essential product engineering, not optional polish.

### Explicitly defer

An unrestricted effect marketplace; arbitrary native/Rust plugins; a second general-purpose GPU compositor; a self-built muxer; a universal server/browser scene language; full collaborative source-code round-tripping; native mobile editors; and broadcast-grade color/HDR guarantees. Add only when a real requirement fails the reused stack.

## 10. Qualification gates before adopting the recommendation

These are proposed acceptance tests, **not tests executed in this research**.

| Gate | Required evidence | Decision it controls |
