# X Player Card launch surface

`/launch` is the public share URL. `/launch/embed` is a minimal, tap-to-play HTML5 player, not an uploaded X video. The 640×360 card is 16:9; the player responsively fits its iframe. Metadata uses absolute `https://fframestudio.vercel.app` URLs. No `twitter:player:stream` is provided: it could bypass our HTML player/codec order.

## Current state: deliberately NOT the film

The committed assets are four-second **PLACEHOLDER / NOT THE LAUNCH FILM** test patterns generated by `python3 tools/launch_media.py --placeholder`. The frame counter is burned in. No outside media, music or screenshots are redistributed. Generator/code and synthetic media are Apache-2.0 under this repository's licence.

`hosted/launch/variants.json` is the source manifest. Every variant has `fps`, `codec`, `url`, `bytes`. Default priority is HEVC/hvc1 1080p120 → H.264 High level 5.1 1080p120 → H.264 High level 4.2 1080p60. Native source selection handles unsupported formats. No refresh-adaptive selection is implemented. The build content-addresses media and poster URLs and refuses stale byte counts. Media is not duplicated in `site/`.

`?debug=1` shows **observed requestVideoFrameCallback callbacks per wall-clock second**, not the file's nominal fps or a physical panel measurement. A 120 fps source on a 60 Hz compositor must not masquerade as 120 displayed fps. Callback resets on pause/seek; a physical 120 Hz phone remains the acceptance gate.

## Security and verification

Only `/launch/embed` (and its `.html`/trailing-slash aliases) permits framing by self, HTTPS x.com/twitter.com and their subdomains. Its CSP keeps `script-src 'self'`, `media-src 'self'`; it has no X-Frame-Options. Disjoint Vercel header patterns keep the original full CSP plus `frame-ancestors 'none'` and `X-Frame-Options: DENY` everywhere else. No script is inline. The player includes no editor/bridge scripts, access token or visitor library.

- `npm run verify:xplayer`: builds the site, uses a free-port static server applying all generated matching headers, parses metadata, checks every emitted non-embed file plus near-miss paths, probes codec/fps/decoded frame counts, checks byte ranges, verifies no autoplay, plays/unmutes, observes callback rate, captures 412×915 and 1440×900 screenshots.
- Fake HTTPS X/Twitter parents and a virtual HTTPS player origin mirror the static server's **unaltered response bytes and headers** to avoid public-parent → loopback mixed-content/local-network policy interference. Chromium itself enforces CSP: X, Twitter and sub.x.com render; evil.test is blocked. This is not a real X post.
- Also included as `hosted: X player card and isolated embed` in `npm run verify`.
- `npm test`, `npm run verify:hosted` remain independent regression gates.

## Preview caveat

Preview deployments use Vercel Authentication (`all_except_custom_domains` protection). Ordinary Twitterbot requests receive an SSO redirect, so X cannot fetch them. Authenticated `vercel curl` after linking the project can verify actual route headers with a bypass; never publish the generated bypass credential. No production deployment or X post is part of this PR.

## Reference / limitations

Rosebud documents the minimal route and X cache/client caveats at https://lab.rosebud.ai/engineering/making-rosebud-games-playable-in-x-posts. Brightcove's player-card guide documents responsive iframe dimensions and width/height metadata: https://studio.support.brightcove.com/social/general/sharing-videos-twitter-player-cards.html. The legacy official X Player Card URL now redirects to the generic developer homepage; it cannot establish a new 2026 maximum. 640×360 is a conventional landscape player size, not a claim that this domain/client is approved. Real X rendering and physical high-refresh playback remain NOT VERIFIED.
